# 10.3 Feature Global — Event Bus (Observer Central)

Central de eventos tipada. Módulos assinam e emitem eventos sem se conhecerem diretamente. **Nenhum módulo importa código de outro módulo** — toda comunicação inter-modular passa pelo `EventBus`.

## Protocolo de comunicação

Toda mensagem emitida no `EventBus` segue um protocolo de nomenclatura que identifica de forma inequívoca a origem, o domínio e a ação do evento:

```
{módulo-ou-domínio}:{recurso}:{ação}
```

Estabelecer e seguir esse protocolo é fundamental. Sem ele, o EventBus vira um caos de strings mágicas espalhadas pelo código, impossível de auditar ou manter.

**Categorias de eventos e seus prefixos:**

| Prefixo | Tipo de mensagem | Responsabilidade |
|---|---|---|
| `auth:` | Autenticação e sessão | Expiração de token, atualização de usuário |
| `ui:toast:` | Notificações visuais | Exibir toasts de sucesso/erro/info/warning |
| `ui:badge:` | Contadores visuais | Atualizar badges com número de eventos (ex: notificações não lidas) |
| `ui:modal:` | Controle de modais globais | Abrir/fechar modais que pertencem ao layout global |
| `cache:` | Invalidação de cache | Sinalizar que um prefixo de cache deve ser invalidado |
| `{module}:` | Eventos de domínio | Eventos específicos de um módulo que outros precisam reagir |

**Regras do protocolo:**

1. **Todo novo evento deve ser registrado em `eventBus.types.ts` antes de ser usado** — nunca emitir strings não tipadas.
2. O payload deve ser completamente tipado — proibido `any` ou `unknown`.
3. Eventos de UI (`ui:toast:show`, `ui:badge:update`) são consumidos por componentes globais de layout, nunca por módulos de negócio.
4. Eventos de domínio (`inventory:product:updated`) podem ser consumidos por qualquer módulo que precise reagir — sem acoplamento direto entre os módulos.
5. Ao emitir `cache:invalidate`, incluir o prefixo exato a ser invalidado no payload — o `CacheService` reage automaticamente.
6. O handler de um evento deve sempre ser removido no cleanup (`useEffect` return) para evitar memory leaks.

**Exemplo de fluxo completo: módulo A atualiza, módulo B reage**

```
ModuloA.service          EventBus                  ModuloB.hook
     |                      |                           |
     |── inventory:product:updated ──────────────────>  |
     |                      |                    reagir à atualização
     |── ui:toast:show ────────────────────────────────> ToastContainer
     |                      |                           |
```

Nenhum módulo sabe da existência do outro. Cada um reage ao evento que lhe compete.

## Estrutura

```
src/services/eventBus/
├── eventBus.ts             ← Facade público
├── eventBusCore.ts         ← Implementação do pub/sub
└── models/
    └── eventBus.types.ts   ← Catálogo de todos os eventos e seus payloads
```

## Implementação

```ts
// src/services/eventBus/models/eventBus.types.ts
/**
 * @description Catálogo centralizado de todos os eventos da aplicação.
 * Toda comunicação entre módulos passa por aqui.
 * Ao criar um novo evento, registrá-lo obrigatoriamente neste arquivo.
 */

export interface EventMap {
  // Auth
  'auth:session:expired': Record<string, never>;
  'auth:user:updated': { userId: string };

  // UI
  'ui:toast:show': { type: 'success' | 'error' | 'info' | 'warning'; message: string; duration?: number };
  'ui:badge:update': { module: string; count: number };

  // Cache
  'cache:invalidate': { prefix: string };

  // Inventory
  'inventory:product:updated': { productId: string };
  'inventory:stock:critical': { productId: string; quantity: number };

  // WebSocket
  'ws:status:changed': { status: 'connecting' | 'connected' | 'disconnected' | 'error' };

  // Orders (exemplo de outro módulo ouvindo eventos do inventário)
  'orders:created': { orderId: string };
}

export type EventKey = keyof EventMap;
export type EventPayload<K extends EventKey> = EventMap[K];
```

```ts
// src/services/eventBus/eventBusCore.ts
/**
 * @description Implementação do pub/sub tipado.
 * Totalmente tipado — impossível emitir evento com payload incorreto.
 */
import type { EventKey, EventPayload, EventMap } from './models/eventBus.types';

type Handler<K extends EventKey> = (payload: EventPayload<K>) => void;
type HandlerMap = Map<EventKey, Set<Handler<EventKey>>>;

const handlers: HandlerMap = new Map();

export const eventBusCore = {
  on<K extends EventKey>(event: K, handler: Handler<K>): () => void {
    if (!handlers.has(event)) handlers.set(event, new Set());
    handlers.get(event)!.add(handler as Handler<EventKey>);
    // Retorna função de unsubscribe
    return () => eventBusCore.off(event, handler);
  },

  off<K extends EventKey>(event: K, handler: Handler<K>): void {
    handlers.get(event)?.delete(handler as Handler<EventKey>);
  },

  emit<K extends EventKey>(event: K, payload: EventPayload<K>): void {
    handlers.get(event)?.forEach(handler => handler(payload));
  },

  /** Remove todos os handlers de um evento específico */
  clear(event: EventKey): void {
    handlers.delete(event);
  },
};
```

```ts
// src/services/eventBus/eventBus.ts
/** Facade público do EventBus */
export const eventBus = eventBusCore;
```

## Uso em um módulo

```ts
// Escutar um evento (geralmente em um hook ou service)
useEffect(() => {
  const unsubscribe = eventBus.on('inventory:product:updated', ({ productId }) => {
    // reagir à atualização
  });
  return unsubscribe; // cleanup automático
}, []);

// Emitir um evento
eventBus.emit('ui:toast:show', { type: 'success', message: 'Produto atualizado!' });
```
