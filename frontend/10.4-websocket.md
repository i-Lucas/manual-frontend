# 10.4 Feature Global — WebSocket Client

Feature global de comunicação em tempo real. Integra diretamente com o EventBus: toda mensagem recebida do servidor via WebSocket é despachada como um evento tipado no EventBus — os módulos reagem via suas subscriptions existentes, sem saber que a origem foi o WebSocket.

> **Implementação padrão:** a feature usa a API nativa `WebSocket` do browser. Se o backend usar Socket.IO, substitua apenas `wsConnection.ts` por uma implementação com `socket.io-client` — o resto do sistema (handler, facade, demo strategy) permanece idêntico.

## Por que é uma feature global

Em praticamente toda aplicação há comunicação em tempo real: contagem de notificações na sidebar, mensagens instantâneas, indicadores de digitação e presença, e sincronização de recursos entre usuários (usuário A edita um produto → servidor notifica todos os clients → cache atualiza → UI reflete a mudança sem recarregar). Centralizar isso evita que cada módulo gerencie sua própria conexão WebSocket.

## Fluxo de sincronização via WebSocket

```
Usuário B edita produto              Servidor WS                  Client do Usuário A
        |                                  |                               |
        |── POST /products/:id ──────────> |                               |
        |                      emite para todos os clients                 |
        |                                  |── inventory:product:updated ─>|
        |                                  |                   EventBus despacha
        |                                  |                               |── cacheService.set(...)
        |                                  |                               |── UI atualiza só o produto
```

Nenhum módulo sabe da existência do WebSocket. Cada um reage ao evento que já conhece — o mesmo que emitiria se o próprio usuário tivesse feito a mudança.

## Estrutura

```
src/services/ws/
├── wsClient.ts              ← Facade público
├── wsConnection.ts          ← Gestão da conexão + reconexão automática
├── wsMessageHandler.ts      ← Parseia mensagens e despacha no EventBus
├── wsDemoStrategy.ts        ← Simulação de WS para modo demonstração

```

## Implementação

```ts
// src/services/ws/models/ws.types.ts
import type { EventKey, EventPayload } from '@/services/eventBus/models/eventBus.types';

/** Envelope de toda mensagem trafegada via WebSocket */
export interface WsEnvelope<K extends EventKey = EventKey> {
  event: K;
  payload: EventPayload<K>;
}

export type WsStatus = 'connecting' | 'connected' | 'disconnected' | 'error';

/** Cenário de simulação registrado pelos módulos no modo demo.
 *  Pode ser async — setInterval não aguarda, mas isso é aceitável para cenários de demo (fire-and-forget). */
export type WsScenarioFn = () => void | Promise<void>;
```

```ts
// src/services/ws/wsConnection.ts
/**
 * @description Gerencia a conexão WebSocket com reconexão automática (exponential backoff).
 * Responsabilidade única: manter a conexão viva. Não sabe nada sobre o conteúdo das mensagens.
 */
import type { WsStatus } from './models/ws.types';

const INITIAL_DELAY_MS = 1_000;
const MAX_DELAY_MS = 30_000;

type OnMessage = (raw: string) => void;
type OnStatusChange = (status: WsStatus) => void;

export function createWsConnection(url: string, onMessage: OnMessage, onStatusChange: OnStatusChange) {
  let socket: WebSocket | null = null;
  let reconnectDelay = INITIAL_DELAY_MS;
  let destroyed = false;

  function connect() {
    onStatusChange('connecting');
    socket = new WebSocket(url);

    socket.onopen = () => {
      reconnectDelay = INITIAL_DELAY_MS;
      onStatusChange('connected');
    };

    socket.onmessage = (event) => onMessage(event.data as string);

    socket.onclose = () => {
      if (destroyed) return;
      onStatusChange('disconnected');
      setTimeout(connect, reconnectDelay);
      reconnectDelay = Math.min(reconnectDelay * 2, MAX_DELAY_MS);
    };

    socket.onerror = () => {
      onStatusChange('error');
      socket?.close();
    };
  }

  return {
    connect,
    disconnect() {
      destroyed = true;
      socket?.close();
    },
    send(data: string) {
      if (socket?.readyState === WebSocket.OPEN) socket.send(data);
    },
  };
}
```

```ts
// src/services/ws/wsMessageHandler.ts
/**
 * @description Recebe mensagens brutas do WebSocket, valida o envelope e despacha no EventBus.
 * Ponto único de conversão: mensagem WS → evento EventBus.
 * O servidor deve enviar JSON com { event, payload } seguindo o protocolo do EventBus.
 */
import { eventBus } from '@/services/eventBus/eventBus';
import type { WsEnvelope } from './models/ws.types';

export const wsMessageHandler = {
  handle(raw: string): void {
    try {
      const envelope = JSON.parse(raw) as WsEnvelope;
      if (!envelope.event || !('payload' in envelope)) {
        console.warn('[WS] Envelope inválido:', raw);
        return;
      }
      eventBus.emit(envelope.event, envelope.payload);
    } catch {
      console.warn('[WS] Mensagem não parseable:', raw);
    }
  },
};
```

```ts
// src/services/ws/wsDemoStrategy.ts
/**
 * @description Simulação de WebSocket para modo demonstração.
 * Módulos registram cenários via addScenario() — eventos periódicos que simulam o servidor.
 * A emissão usa o EventBus diretamente, produzindo o mesmo efeito que uma mensagem real.
 */
import type { WsScenarioFn } from './models/ws.types';
import type { EventKey, EventPayload } from '@/services/eventBus/models/eventBus.types';
import { eventBus } from '@/services/eventBus/eventBus';
import { simulateDelay } from '@/utils/demo.util';

const scenarios: Array<{ fn: WsScenarioFn; intervalMs: number }> = [];
const timers: ReturnType<typeof setInterval>[] = [];

export const wsDemoStrategy = {
  /** Registra um cenário que dispara periodicamente durante o modo demo */
  addScenario(fn: WsScenarioFn, intervalMs: number): void {
    scenarios.push({ fn, intervalMs });
  },

  /** Emite um evento no EventBus com delay simulado (mesma interface que o servidor real) */
  async emit<K extends EventKey>(event: K, payload: EventPayload<K>, delayMs = 600): Promise<void> {
    await simulateDelay(delayMs * 0.8, delayMs * 1.2);
    eventBus.emit(event, payload);
  },

  start(): void {
    for (const { fn, intervalMs } of scenarios) {
      timers.push(setInterval(fn, intervalMs));
    }
  },

  stop(): void {
    timers.forEach(clearInterval);
    timers.length = 0;
    scenarios.length = 0;
  },
};
```

```ts
// src/services/ws/wsClient.ts
/**
 * @description Facade público do WebSocket Client.
 * Seleciona automaticamente entre conexão real e estratégia de demo.
 * Toda mensagem recebida é despachada no EventBus — módulos reagem via subscriptions existentes.
 * Conectar após login bem-sucedido; desconectar no logout.
 * @since 2024-01-15
 */
import { isDemoMode } from '@/utils/environment.util';
import { createWsConnection } from './wsConnection';
import { wsMessageHandler } from './wsMessageHandler';
import { wsDemoStrategy } from './wsDemoStrategy';
import { eventBus } from '@/services/eventBus/eventBus';
import type { EventKey, EventPayload } from '@/services/eventBus/models/eventBus.types';

const WS_URL = import.meta.env.VITE_WS_URL as string;

let connection: ReturnType<typeof createWsConnection> | null = null;

export const wsClient = {
  connect(): void {
    if (isDemoMode()) {
      wsDemoStrategy.start();
      return;
    }
    connection = createWsConnection(
      WS_URL,
      (raw) => wsMessageHandler.handle(raw),
      (status) => eventBus.emit('ws:status:changed', { status }),
    );
    connection.connect();
  },

  disconnect(): void {
    if (isDemoMode()) {
      wsDemoStrategy.stop();
      return;
    }
    connection?.disconnect();
    connection = null;
  },

  /** Envia uma mensagem ao servidor (somente modo real) */
  send<K extends EventKey>(event: K, payload: EventPayload<K>): void {
    if (isDemoMode()) return;
    connection?.send(JSON.stringify({ event, payload }));
  },
};
```

## Integração com AuthProvider

O WebSocket é conectado logo após o login e desconectado no logout — pois normalmente requer autenticação.

```ts
// Dentro de AuthProvider (src/contexts/AuthContext/AuthProvider.tsx)
const login = useCallback((u: AuthUser, token: string) => {
  authStorage.save(u, token);
  setUser(u);
  wsClient.connect(); // conecta após autenticação bem-sucedida
}, []);

const logout = useCallback(() => {
  wsClient.disconnect(); // desconecta antes de limpar a sessão
  authStorage.clear();
  setUser(null);
}, []);
```

## Cenários de demo por módulo

Cada módulo com eventos em tempo real registra seus próprios cenários no arquivo `demo/wsScenarios.ts`. Eles são iniciados automaticamente quando `wsDemoStrategy.start()` é chamado.

```ts
// src/modules/Messages/demo/wsScenarios.ts
/**
 * @description Cenários de WS para o módulo de mensagens no modo demonstração.
 * Registrados antes de wsClient.connect() ser chamado.
 */
import { wsDemoStrategy } from '@/services/ws/wsDemoStrategy';

export function registerMessagesDemoScenarios(): void {
  // Simula indicador de digitação a cada 12 segundos
  wsDemoStrategy.addScenario(() => {
    wsDemoStrategy.emit('messages:user:typing', {
      userId: 'demo-user-1',
      conversationId: 'conv-demo',
    });
  }, 12_000);

  // Simula nova mensagem a cada 45 segundos
  wsDemoStrategy.addScenario(() => {
    wsDemoStrategy.emit('messages:new', {
      id: `msg-${Date.now()}`,
      content: 'Olá! Estou testando o sistema.',
      senderId: 'demo-user-1',
      conversationId: 'conv-demo',
      timestamp: new Date().toISOString(),
    }, 1_200);
  }, 45_000);
}
```

```ts
// src/modules/Inventory/demo/wsScenarios.ts
import { wsDemoStrategy } from '@/services/ws/wsDemoStrategy';

export function registerInventoryDemoScenarios(): void {
  // Simula atualização de estoque por outro usuário a cada 60 segundos

```

Os cenários são registrados centralmente no `AuthProvider` (ou em um hook de inicialização do app) antes de `wsClient.connect()`:

```ts
// Chamado no AuthProvider logo antes de wsClient.connect()
function registerAllDemoScenarios() {
  registerMessagesDemoScenarios();
  registerInventoryDemoScenarios();
  // ... demais módulos
}

const login = useCallback((u: AuthUser, token: string) => {
  authStorage.save(u, token);
  setUser(u);
  if (isDemoMode()) registerAllDemoScenarios();
  wsClient.connect();
}, []);
```

## Como um módulo reage a eventos WS

Nenhuma mudança necessária. O módulo já assina eventos no EventBus normalmente — não importa se o evento veio de outro módulo via `eventBus.emit()` ou do servidor via WebSocket. O mecanismo é o mesmo.

```ts
// Hook do módulo de mensagens — reage a eventos de WS sem saber que são de WS
useEffect(() => {
  const unsub = eventBus.on('messages:new', ({ id, content, senderId }) => {
    setMessages(prev => [...prev, { id, content, senderId }]);
    eventBus.emit('ui:badge:update', { module: 'messages', count: unreadCount + 1 });
  });
  return unsub;
}, [unreadCount]);
```
